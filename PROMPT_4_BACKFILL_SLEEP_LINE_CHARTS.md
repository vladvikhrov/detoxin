## ФИЧА 1. Отметка привычки за прошедшие дни

Сейчас отметить привычку можно только за сегодня (`HabitsViewModel.toggleToday`, виджет). `HabitDao.toggleHabit(habitId, dateEpochDay)` уже принимает любую дату — DAO менять не нужно.

1. ViewModel:
   - `HabitsViewModel.toggleDay(habitId: Long, epochDay: Long)` через существующий `write { }`, с обновлением виджетов (`refreshWidgets()`), если затронут сегодняшний день.
   - Валидация: будущие дни отклоняются; глубина — не дальше 60 дней назад (константа `BACKFILL_WINDOW_DAYS`).
   - `toggleToday` переписать как вызов `toggleDay(habitId, LocalDate.now().toEpochDay())`.
2. Карточка привычки в списке (`HabitsScreen`): под названием ряд из 7 кружков за последние 7 дней (буква дня недели + состояние). Тап по кружку прошлого дня ставит или снимает отметку. В `HabitItemUi` добавить `lastSevenDays: List<DayMark>` (`epochDay`, `isCompleted`, `isToday`).
3. `HabitDetailSheet`: календарь месяца (сетка 7×N, неделя с понедельника) с переключением месяцев стрелками в пределах окна backfill. Выполненный день — залитый круг цвета привычки, невыполненный — контур, будущие и вне окна — неактивные (alpha 0.38).
4. UX:
   - Снимать отметку можно сразу, но с Snackbar «Отметка за 3 окт. снята · Отменить».
   - Haptic feedback при тапе (`LocalHapticFeedback`, `HapticFeedbackType.LongPress`).
   - Серия, прогресс цикла, темп месяц-к-месяцу и графики пересчитываются автоматически через существующие Flow — проверь, что `HabitStatsCalculator` не кэширует «сегодня» так, что старые дни не учитываются.
5. Accessibility: у каждого дня `contentDescription` вида «Пятница, 10 октября, выполнено» и `Role.Checkbox`.

## ФИЧА 2. Режим «Отбой» (контроль сна)

Проблема: перед сном пользователь выключает службу Detoxin в настройках специальных возможностей и сидит в TikTok до 2 часов ночи. Кроме того, в `UsageBudget.decide` дневной лимит обнуляется в полночь, поэтому в 00:00 TikTok снова даёт целый час.

### 2.1 Окно сна и строгий лимит
- Настройки в DataStore Preferences (не в Room): `bedtimeStart` (по умолчанию 23:30), `wakeTime` (07:00), `enabled`, `nightAllowanceMinutes` (по умолчанию 0, допустимо 0–15).
- Новый объект `BedtimePolicy` (пакет `com.detoxin.app.usage`) с чистыми функциями без Android-зависимостей:
  - `isInBedtime(nowWall, zone, settings): Boolean` — корректно обрабатывает окно через полночь;
  - `bedtimeWindowStart(nowWall, zone, settings): Long` — начало текущего окна (вчерашнее, если сейчас 01:00).
- `LimitBlock.Kind` дополнить значением `BEDTIME`, `untilWall` = время подъёма.
- `UsageBudget.decide` приоритеты: BEDTIME → DAILY → HOURLY. В окне сна суммарное время всех `TrackedApp` с начала окна сравнивается с `nightAllowanceMinutes`; при 0 блокировка срабатывает сразу при открытии.
- Блокировка в окне сна распространяется и на детекторы Shorts / VK-клипов / ленты (`DetoxinAccessibilityService.detectBlockedScreen`).
- Экран блокировки (`OverlayManager`) для BEDTIME: тёмная тема, текст «Время спать. TikTok откроется в 07:00» и кнопка «Закрыть приложение». Кнопки «ещё 5 минут» нет.

### 2.2 Ночь не обнуляет лимит
- Пока длится окно сна, дневной лимит после полуночи не сбрасывается: использование с начала окна (например, с 23:30 предыдущего дня) входит в бюджет. Свежий дневной бюджет появляется только после `wakeTime`.

### 2.3 Защита от отключения в момент слабости
Запретить выключение службы нельзя и не нужно. Задача — сделать его осознанным и видимым:
- Изменение настроек «Отбоя» во время окна сна: можно только ужесточить (раньше начало, меньше allowance). Ослабление вступает в силу со следующего дня, о чём UI сообщает явно.
- Учёт отключений: новая сущность Room `ProtectionGap(id, startedAtWall, endedAtWall: Long?)`. Начало пишется в `onUnbind` / `onDestroy` службы, конец — в `onServiceConnected`. Если процесс убит без `onUnbind`, при старте закрыть «висящий» разрыв по последнему heartbeat (метка времени в DataStore, обновляется трекером не чаще раза в минуту).
- После включения службы — уведомление-итог: «Защита была выключена 23:47–02:10. За это время TikTok: 1 ч 52 мин». Время берётся из `UsageStatsReader.readSessions`: статистика пишется системой даже при выключенной службе.
- Канал уведомлений `bedtime`, разрешение `POST_NOTIFICATIONS` запрашивать только на API 33+.

### 2.4 Напоминание перед сном
- За 30 минут до `bedtimeStart` — тихое уведомление «Через 30 минут отбой». Планировать через `AlarmManager.setAndAllowWhileIdle` (без точных будильников и разрешения `SCHEDULE_EXACT_ALARM`). Перепланировать после `BOOT_COMPLETED` и изменения настроек — по образцу `MidnightRefreshScheduler`.

### 2.5 Статистика сна
- В `AnalyticsScreen` новая карточка «Ночное время» (только при включённом режиме):
  - линейный график (компонент из фичи 3): минуты в TikTok / YouTube за окно сна по ночам, за 7 или 30 ночей;
  - метрика «Отбой фактически»: время последнего использования отслеживаемого приложения в окне сна, например «в среднем 01:12, неделю назад 01:48»;
  - число ночей с отключённой защитой (из `ProtectionGap`).
- Автопривычка «Лёг вовремя»: опция при создании привычки `autoSource = BEDTIME`. Отметка ставится автоматически утром (после `wakeTime`), если в окне сна было не больше `nightAllowanceMinutes` использования и не было `ProtectionGap`. Поле `autoSource: String?` в `Habit` добавляется миграцией 2→3 (`DEFAULT NULL`). Для автопривычки ручная отметка тоже доступна — ручная правка имеет приоритет.

### 2.6 Экран настроек
- Раздел «Отбой» (доступен с вкладки «Использование», иконка луны в TopAppBar): переключатель, два `TimePicker` (Material 3), слайдер ночного лимита 0–15 мин, пояснение, как работает защита от ослабления.

## ФИЧА 3. Линейные диаграммы вместо столбцов

Пользователь хочет видеть рост и падение линией, а не столбцы. За основу взять `SmoothBezierLineChart` (монотонный сплайн Фрича–Карлсона, морфинг, тултип) и обобщить его.

1. Новый компонент `TrendLineChart` в `ui/common/charts/`:
   - `series: List<LineSeries>`, где `LineSeries(label: String, color: Color, values: List<Float?>)`; `null` — разрыв линии (будущие дни, дни до создания привычки);
   - `xLabels: List<String>`, `yFormatter: (Float) -> String`, `yMax: Float?` (для процентов фиксировать 1f);
   - `referenceLine: ReferenceLine?` — горизонтальный пунктир (лимит экранного времени, норма привычки 100%) с подписью;
   - заливка-градиент под линией только для первой серии, точки-маркеры на значениях, крупная точка на последнем значении;
   - тултип по тапу/drag показывает значения всех серий в точке;
   - стрелка тренда в заголовке: сравнение среднего за вторую и первую половину периода, «▲ +12%» / «▼ −8%». Для экранного времени рост окрашивается в `error`, для привычек — в `primary`.
   - Вся геометрия в `drawWithCache`, анимация читается только в фазе отрисовки (как в существующих графиках).
2. Замены:
   - `HabitTrendBarChart` → `TrendLineChart` в `HabitDetailSheet` (доля выполнения за неделю / месяц / год, пунктир 100%). Старый файл удалить.
   - `StackedBarChart` → `TrendLineChart` на экране аналитики: три линии (TikTok, YouTube, остальные), пунктир лимита. Для диапазона «День» — по часам. Легенду `UsageLegend` сохранить. Старый файл и `StackedBarColors` удалить, если они больше нигде не используются.
   - `SmoothBezierLineChart` («Спасённые открытия») перевести на `TrendLineChart` с одной серией, чтобы осталась одна реализация.
   - `HabitWeekdayFrequencyChart` (Пн–Вс) и `HabitHeatmap` НЕ трогать: это категориальные данные, линия между днями недели вводит в заблуждение.
3. Accessibility: `Modifier.semantics { contentDescription = ... }` с текстовым резюме графика («Экранное время за 7 дней: снижение с 2 ч 10 мин до 1 ч 05 мин»).
